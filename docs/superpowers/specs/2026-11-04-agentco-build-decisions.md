# agentco — build decisions for Plans 2–5

*Date: 2026-11-04 · Companion to [the design](2026-11-04-agent-company-design.md). These settle what the design's §15 "Left to the builder" leaves open, so every plan builds on the same choices. All are the builder's calls; change any of them and the later plans follow.*

| # | Question | Decision | Why |
|---|---|---|---|
| D1 | How do agents call models? | One `LLMClient` protocol in `agentco/llm/`, implemented with **LiteLLM** (`litellm.acompletion`). The role's `model` in tenant config is a LiteLLM model string (e.g. `anthropic/claude-sonnet-4-5`, `openai/gpt-5`, `gemini/gemini-2.5-pro`). Cost per call comes from LiteLLM and goes to `TaskStore.record_cost`. Tests use a scripted `FakeLLM`. | One API across Anthropic / OpenAI / Google, which the per-role families need (§10). |
| D2 | How do engineers edit code? | Our own small **tool loop**: the model gets tools `read_file`, `write_file`, `replace_in_file`, `list_dir`, `search`, `run` (only commands from `.agentco.yml`), `finish(summary)`. Every path is confined to the task's worktree. A max-turns limit; hitting it counts as "stuck" (junior → escalation). | Keeps role isolation and audit in our code; no dependency on an external agent CLI. |
| D3 | Sandbox | A **git worktree per task** under `.agentco/worktrees/<task-id>`, branch `agentco/task-<id>`. Commands run as subprocesses with a timeout. If `.agentco.yml` names a compose file / devcontainer, commands run through `docker compose run` instead; that path is unit-tested by the command it builds. | Spec §5 asks for worktree + container; worktree-only works on any machine. |
| D4 | QA's view of the code | QA gets a **separate worktree** of the same commit with history squashed into one neutral commit (`agentco: snapshot`), so it never sees commit messages or notes. | Spec §7 "commit messages squashed/neutralised". |
| D5 | GitHub access | A `GitHub` protocol backed by the **`gh` CLI** (subprocess, JSON output). Reads: issues, PRs, review comments, PR files. Writes: push branch + `gh pr create` / `gh pr edit` only — never merge. Tests use a fake. | `gh` handles auth; the system only reads and opens PRs (§2 non-goals). |
| D6 | Code structure | **tree-sitter** (`tree-sitter` + `tree-sitter-language-pack`), following FalkorDB/code-graph's model (File, Class, Function, DEFINES / CALLS edges). Written with plain Cypher into the **`{tenant}__rnd`** graph (outside Graphiti's episodes), keyed by repo-relative `path` and `name`. A comment on *file + line* is linked to the innermost function/class containing that line. FalkorDB/code-graph itself is a demo app, not a library, so we reuse its approach, not its package. | Spec §8 keeps code inside `rnd` so *comment → function → risk* is one graph. |
| D7 | Workflow engine | Plain state machine on the existing `TaskStore` (SQLite or Postgres), run **in-process and synchronously** by `agentco task run <id>`. No queue service, no Temporal in v1. | v1 is local-first (§14). |
| D8 | Human on the loop | CLI first: `agentco inbox` lists tasks waiting for a human; `agentco decide <id> approve|reject|answer --note "..."` records a `HumanDecision`. Later a GitHub label/comment can feed the same command. | Spec §15 "start simple". |
| D9 | PR feedback intake | **Polling**, `agentco intake --repo owner/name` (run by hand or cron), with a per-repo cursor in `meta`. Webhooks belong to the hosted mode, not v1. | Local-first; no public endpoint needed. |
| D10 | Similarity / "new" thresholds | A task is "known" when memory search for its title+criteria returns ≥ 1 rnd `Issue`/`Playbook` fact; otherwise "new". Exact thresholds are config (`thresholds:` in tenant config) with these defaults. | Simple, explainable, tunable. |
| D11 | Prompts | One file per role under `src/agentco/agents/prompts/<role>.md`, loaded at runtime. Every role's reply is **structured JSON validated by pydantic**; an invalid reply is retried once, then counts as a failed step. | Deterministic orchestration around non-deterministic models. |
| D12 | Testing | No real LLM, GitHub or Docker in unit tests (FakeLLM, FakeGitHub, MemoryBackend fake, temporary git repos). Each plan ends with an `integration`-marked smoke test that is skipped unless its env vars are set. | Same rule as Plan 1. |
